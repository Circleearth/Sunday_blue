- **番茄钟动态气泡**：在“节奏与提示音”可开关人格动态反馈。启动时实际请求角色 API 检查连通；后台生成，失败/超额用固定台词，计时不等网络。综合四项人格、长期好感度和短期情绪；按角色保留当天最近 12 条侧栏上下文（6轮）；本轮结束释放运行状态，跨轮继续当天语境，缓存最长7天。界面仍保留最近 20 条气泡，不写入私聊或长期记忆。
- **调用限制**：至少间隔 10 秒、每次输出最多 120 Token；全应用每天最多 60 次，并有每轮24KB、每日100KB的保守输入预留预算（不是实测Token）。连接失败60秒后允许再试。快速暂停会撤销过时的启动回复，避免晚到气泡与当前状态冲突。自动循环和 1–20 轮上限继续保留。

## 新的日常入口（2026-11-10）

重启源码版后，顶部可切换 **专注、聊天、会议、商店、关系**，默认先进入专注。原有聊天、人格、记忆与插件设置继续保留。

- **番茄钟**：大号圆环倒计时，可切换专注 / 短休息 / 长休息，默认 25 / 5 / 15 分钟，每完成 4 个番茄建议长休息。到点自动结算并提醒，下一阶段由你点击开始。严格超过 2 分钟的专注才计有效记录；休息不发金币。提前结束按实际有效时长结算，但不算完成一个番茄。短气泡不占长期对话历史。
- **商店**：可添加娱乐时间、兴趣活动、现实预算奖励和角色心意。金币与真实预算独立，实际支出必须再确认。休息不需要购买。
- **关系**：分别展示长期关系与会自然平复的情绪。未记录不会被当作未完成，负面事件只由你明确报告，礼物不是恢复关系的必需品。
- **会议**：创建群并选参与角色。每位角色默认参考自己的最近私聊和记忆，不直接读取其他角色私聊；群里公开说出的内容成为共同经历。私聊也会衔接刚才群聊，未总结时同样有效。“结束话题并总结”生成共同摘要，已启用 LivingMemory 的参与者会进入各自记忆队列。
- **主动交流**默认关闭。在会议设置中选择目标群、预算、冷却和静默时段；群需明确允许分享专注事件才会围绕现实记录主动交流。可另行开启轻松闲聊和 Rui 会后私聊。只在软件进程运行时工作。
- **设置 → 角色权限 → 独立模型与推理** 可给 Rui 等角色选择独立模型、连接、推理参数和轻互动模型。未知供应商不会被假定支持高推理，请用测试连接确认。会议页可查看近期模型、耗时、Token 与错误记录。

现实记录、金币、预算和群聊保存在独立的 `data/modules.sqlite3`，角色只是参与者，不随角色删除而清空。Ollama 仍需手动启动，群聊与各角色共用这一服务。新模块说明、已知限制与后续维护入口见 [模块索引](docs/MODULE_INDEX.md)。

交给 Claude 继续制作时，先读 [当前 Handoff 任务](handoff/codex-to-claude.md) 顶部：核心链路已实现，后续按限定范围逐个完善页面，不重新设计账本、记忆隔离或角色删除。

**番茄钟声音设置**：打开专注页右上角“节奏与提示音”，可调整三种时长、长休息间隔，并为专注／短休息／长休息分别选择 MP3 或 WAV、试听、恢复默认音效、调音量或关闭声音。音频不超过 20 MB，自动复制至 `data/sounds/focus/`，不依赖原文件；单次最多播放 30 秒、不循环，页面提供停止按钮。设置时长从下一轮生效。切到其他页面或最小化仍可提醒；完全退出软件或电脑休眠不会继续计时，重开后从暂停状态恢复。旧版未结束的正计时保留原样，手动结束后即可使用新番茄钟。

## 自定义角色与维护入口

最右侧 **角色 → 管理** 可创建、重命名、归档、恢复、导出与永久删除角色；设置 → 人格设定也提供入口。新角色会同步出现在聊天、权限、人格、字体与记忆选择器中。名称可改，内部 ID 始终不变；ID 不需要手工填写。新角色人格可在原编辑器补充。

归档保留全部数据并停止使用，至少保留一个启用角色。永久删除需先归档，再核对范围并输入显示名称。正在聊天/记忆操作、打开的图谱、待发送 QQ 提醒、启用的 MCP 绑定或未知插件数据会阻止删除。先通过原插件取消提醒、解除绑定；软件不会猜测清除外部任务。

删除前自动保存 `data/role_operations/<操作 ID>/backup.zip`，包括角色专属文件、会话原文和配置；备份含个人资料，请妥善保管。故障后角色保持停用，重启或点击“继续未完成的删除”可续做。共享插件代码、Ollama 模型、其他角色、外部工作区和全局 API 连接均保留；离线历史备份不参与记忆检索，也不会自动擦除。

注册文件是 `data/roles.json`，不要用显示名称重命名数据目录。架构审查、已知限制和实施顺序见 [角色系统审查](docs/ROLE_SYSTEM_REVIEW.md)；后续开发请先读 [维护地图](handoff/MAINTENANCE_MAP.md)。会话删除仅删除原文与来源队列，**不清除已经提炼的角色记忆**；需完整移除角色数据时使用角色管理。

**设置 → 角色权限 → 配置此角色的能力、职责与按需加载**：可单独开关文件、确认记忆和 MCP 能力，并编辑职责范围。已有插件/Skill 绑定可选择“每轮加载”或“按需加载”，支持关键词或 `@skill:目录名` / `@plugin:插件ID` / `@files`。模型也可从已授权目录中申请加载，申请成功后的下一次请求才带完整内容。加载不会扩大权限，记忆写入仍需确认。设置完成需保存外层设置。老角色默认行为保持，新角色默认不启用任何原生插件、不开放文件/MCP，需要你按需配置。

## 启动与首次配置

1. 双击 **SundayBlue.exe** 使用已打包版本；**Start Sunday Blue.cmd** 优先启动 EXE。要使用最新源码，双击 **Start Sunday Blue Source.cmd**，或运行 `py -3 main.py`。
2. 右上角 **设置 → API 连接**：填写协议、请求地址、API Key、模型 ID。
3. 如果你的 cc-switch 中转站支持 Anthropic Messages，选 **Anthropic Messages**；鉴权按服务商要求选 `x-api-key` 或 `Bearer`。如果服务商提供 OpenAI 兼容接口，选 **OpenAI 兼容 Chat Completions**。
4. 点击 **测试连接**，成功后 **保存设置**。测试会发送一次短请求，产生少量 API 用量。
5. 点击最右侧角色头像开始聊天。Enter 发送，Shift + Enter 换行。

**不需要额外声明“调用插件”或“使用 Skill”。** 此软件不调用 Claude Code / Codex CLI，也不继承 Claude Desktop 登录状态。它使用你填写的 API 配置；可手动填入与 cc-switch 相同的配置，不会读取或修改 cc-switch、Claude 的配置。

模型 ID 不预填，避免假定你的中转站支持某个模型。地址支持根地址、`/v1` 地址或完整 `/v1/messages`、`/v1/chat/completions` 端点。例如：

| 协议 | 填入地址 | 最终请求 |
|---|---|---|
| Anthropic | `https://your-relay.example` | `https://your-relay.example/v1/messages` |
| Anthropic | `https://your-relay.example/v1` | 同上 |
| OpenAI 兼容 | `https://your-relay.example/v1` | `https://your-relay.example/v1/chat/completions` |

API Key 使用当前 Windows 账户的 DPAPI 加密，保存在 `data/settings.json`。没有密钥的本地代理也可使用。网络证书验证保持开启。程序不自动重试外部操作。

## 界面与会话

- 左侧：当前角色的历史会话、新对话、重命名、Markdown 导出。
- 中间：自适应聊天气泡，成功工具调用与回执不展示，失败只显示失败说明；文字与代码可选中复制。
- 右侧：角色立绘、上下文用量、持久记忆入口。
- 最右侧：九个角色头像，滚轮可查看下方角色。点击立即切换；发送中的任务在后台继续。
- 顶部边框：拖动移动；双击最大化/还原；右上角最小化/最大化/关闭；右下角可拖拽调整大小。

**消息流式到达时按微信式跟随**：你位于对话底部，新消息（你发的、Agent 流式、工具回执、分段揭示）自动跟随到底；你向上拉历史时新消息不会把视图拽走，聊天区底部浮出"⌄ 查看最新消息"按钮，点击回到最新并恢复自动跟随。切换会话/角色后回到该会话底部。渲染为增量追加：同会话新消息只插入新气泡，已显示内容不重排，因此不再有整块闪烁与跳顶。实现见 `sunday_blue/ui.py` 的 `render()`（增量路径）与 `tests/test_chat_follow.py`。

每个会话有独立历史。同角色会话共享 **该角色自己的** 持久记忆，不共享其他角色的记忆。不同角色可同时请求模型；切换不会重建人格。未发送草稿在当前软件进程中按会话保留，退出时草稿不持久保存。重开后恢复上次角色及已选择的会话。

**分支** 复制当前完整会话和压缩摘要，原会话不受影响。当前会话正在生成时，需要等待或停止后分支。

输入 **`/compact`** 可压缩上下文，会真正请求模型生成历史摘要，后续请求使用摘要和新消息，原始消息仍留在数据库。摘要失败或被截断时不替换上下文。建议在接近容量之前压缩；若已经超过服务商的请求限制，压缩请求也可能失败。压缩会产生 API 用量，不代表模型拥有无限精确记忆。

右侧显示上下文用量；当前 UI 已移除上下文详情按钮。容量是设置中的手动值，必须与你选择的模型一致；有 usage 时显示最近一次 API 报告的输入与输出合计，无 usage 时仅估算历史字符，不包含完整系统提示和工具 schema，不冒充精确实时 token 数。

点击“停止并撤回”后协作取消生成，线程退出后把本轮用户消息放回输入框，同时移除本轮回复/工具回执；原内容保留在本地 audit。聊天网络读取最长等待约 60 秒；首次启动记忆核心或本地向量请求可能需要更久。已有新草稿会接在撤回文本之后。已执行的文件或外部操作不会回滚。

**设置 → 外观 / 数据**可开启“关闭窗口后留在系统托盘”，源码模式无需打包也能后台继续回复；托盘可打开或退出。默认关闭此选项，退出时需先结束任务；休眠、注销、关机不继续运行。异常退出时缺失工具回执会标注“结果未知”，不会自动重放操作。

## 聊天气泡、字体与分段

输入框已移除灰色占位文案，拼音预编辑交给 Qt 原生输入法处理。切换深浅色只更新现有气泡颜色，保留阅读位置。

气泡短文收窄，长文最大宽度为聊天可用区域的 **80%**，窗口缩放后重新排版。高度随内容展开，没有气泡内部滚动条；长消息通过整个聊天区域滚动阅读。仅含换行/空格的文本不创建气泡，成功工具回执保留在数据库但不显示，失败/拒绝显示简短说明。

**设置 → 外观 / 数据** 将界面字体与气泡字体分开。界面字体只提供思源黑体、微软雅黑 UI、等线、幼圆四个中文适配选项，括号标注风格；界面字号由设计系统固定。气泡字体按九个角色分别保存，每个角色都有符合性格的推荐字体、字号和字重，也可单独导入 `.ttf` / `.otf` / `.ttc`。字体复制到 `assets/fonts`，不会影响其他角色。导入失败不应用；只导入你有权使用的字体。

界面现由统一设计变量控制深浅色、文字、间距、圆角和组件状态。维护规则见 [UI 设计系统](docs/UI_DESIGN_SYSTEM.md)。修改字体后只重排气泡，不会清空正在等待显示的分段。

同一页可设置短回复分段：默认启用，阈值 **150 字**，只有总字数严格小于阈值才分段；等于或超过阈值的长回复完整显示、不分段。默认正则 `.*?[。？！~…]+|.+$`，匹配终点为分段点，保留标点与未匹配内容。无匹配、无效正则或执行超时会回退为完整一段，不丢正文；保存时拒绝语法错误的正则。

- `random`：随机间隔，默认 **1.5–3.5 秒**。
- `log`：按上一段字数计算 `log_base(字数)` 秒；底数必须大于 1，默认 10。

启用分段时短回复等完整正文到达后逐段显示；流式回复一旦达到阈值就按长消息继续流式显示。关闭分段恢复直接流式展示。历史会话立即展示所有分段，不重放延迟；当前进程切换角色时分段计时继续。分段只是显示效果，数据库和后续模型上下文仍保留原始完整消息，不增加 API 请求。

新环境需 `py -m pip install -r requirements.txt`；分段使用带超时支持的 regex 库，本机已安装。已打开的旧窗口需要从托盘退出后再启动，才能加载更新；EXE 只在重新打包后包含新的主程序代码。

## 角色文件权限与编辑

**设置 → 角色权限**：选角色，再添加 **只读目录** 或 **可写目录**。初始权限为空。可写目录同时允许读取。权限针对所选目录及其子目录；每个角色单独配置。

可让角色列目录、读取/搜索 UTF-8 文本、新建与精确编辑文件、创建目录、移动文件/目录，以及删除文件/目录。仅允许角色授权范围内的绝对路径；授权根目录本身不可删除或移动。单文本文件最大 1 MiB，搜索最多 1500 文件、100 命中。

**设置 → 角色权限 → 选中可写目录 → 信任 / 取消信任所选工作区 → 保存设置**。信任按角色和目录保存；信任范围内的文件操作自动确认，普通可写目录仍展示审阅。只读目录不能设为信任。信任不会扩大访问范围，也不免除持久记忆或 MCP 的确认。

修改保留旧字节到 `data/backups`；删除先完整复制到 `data/backups/deleted/<编号>/`，其中 `restore.json` 记录原位置。恢复时可按映射手动复制回去。删除单次最多 10000 项 / 512 MiB，目标变化则中止；拒绝链接/联接点/硬链接。移动只支持同卷且不覆盖目标。所有实际操作有审计记录。

没有任意 shell、终端执行、运行测试命令或通用二进制编辑工具。软件目录不能授予外部文件工具；目录检查并非针对恶意本机并发进程的操作系统沙箱。

## 记忆、人格、旧资料

**设置 → 人格设定 → 打开人格编辑器**：九个角色分别维护身份内核、性格与反应、说话方式、角色关系。对应 `personas/<角色 ID>/identity.md`、`personality.md`、`voice.md`、`relationships.md`。可切换角色和栏目，保存前左右对比，每次保存留完整版本；“载入上一版”仍需审阅保存才生效。模型没有改写人格的工具。版本在 `data/persona_versions/<角色 ID>/`。编辑器的确认保存独立生效，取消外层设置不会撤销它。

旧 `expertise.md / rules.md / responsibilities.md` 已原样归档到 `personas/_archive/<角色 ID>/`，不再注入。角色专属能力以后由插件承担。APP 不加载 `Main-rui/CLAUDE.md` 或其 @ 引用，不维护一套重复的人格哈希启动流程。宿主权限由程序统一实施。

**右侧 → 编辑已确认记忆**：`data/memory/<角色 ID>/long_term.md` 保留作为你确认过的事实、偏好和约定，可在 APP 中直接编辑。你保存或模型提出修改时均可左右查看修改前后；模型更新始终需要确认，信任工作区不免除记忆审阅。旧字节保存在 `data/backups`。已授权但未信任的文件目录同样逐次确认；未授权目录不允许写入。

**自动历史记忆**由下述 LivingMemory 管理，与已确认记忆分开标注。自动摘要可能有误，不冒充用户确认；不会自动覆盖 `long_term.md` 或人格。没有迁移任何旧聊天库或 AstrBot 的既有记忆。

## LivingMemory 与独立 Ollama

已接入 **LivingMemory 2.9.1 原版核心和图谱界面**，不是仅模仿记忆提示词。每个角色独立进程、SQLite、向量索引、记忆原子和图谱，同角色多个会话共享记忆。

1. 重启源码版 Sunday Blue，点击右侧 **记忆大脑 / Ollama**。
2. 点击 **启动 Ollama**。软件启动、状态检测、普通聊天都不会自动启动 Ollama。
3. 选择角色，勾选 **为此角色启用自动记忆**。也可在设置 → 插件按角色启用 LivingMemory；新插件默认不启用。
4. 点击 **打开记忆图谱**，在应用内使用原版 2D/3D 图谱、记忆管理、召回测试和高级参数页面。
5. 默认每 **4 轮完整对话**整理一次，可在插件参数中调整；也可点击 **立即整理待处理对话**。模型整理失败保留待处理内容并显示错误。

本机已准备独立的 `runtime/ollama/ollama.exe`、运行库和 `runtime/ollama/models`，使用 `127.0.0.1:11435`，默认 `bge-m3:latest`。它们从你指定的 Ollama 分发及本机模型复制而来，运行时不依赖 Rui-bot 的目录，也不使用其 11434 端口。正常退出会关闭本软件启动的记忆服务和 Ollama；启停不会终止其他 Ollama 实例。异常退出留下的独立 Ollama 可在任务管理器按程序路径辨认；软件不接管未知进程。

向量计算使用本地 Ollama；记忆摘要使用 Sunday Blue 当前 API 连接，因此有额外 API 用量。仅完整成功轮次进入持久队列，工具回执和隐藏思考不进入。Ollama 关闭时聊天继续，完整对话仍进入待整理队列；再次手动启动 Ollama，并打开该角色图谱或发送消息后恢复处理。失败或取消的回复不入库，旧聊天不会自动批量补录。手动停用插件停止新增和自动整理，历史记忆仍保留。

记忆数据：`data/plugins/livingmemory/<角色 ID>/`；确认记忆仍在原位置。整理模型不是自动自我改写人格的权限通道。原版高级设置中的 AstrBot 会话触发规则不控制桌面轮次队列，桌面触发轮数以插件参数为准；核心参数保存后建议关闭并重开记忆服务以完整应用。

源码安装与维护、升级差异检查见 [LivingMemory 接入说明](docs/LIVINGMEMORY.md)。独立 Python 环境和 Ollama 模型在 `runtime/`，体积较大，不提交 Git；复制整套软件应保留该目录。重新安装 Python 依赖可运行 `scripts/setup_livingmemory.ps1`（目前依赖锁针对 Python 3.14）。

## 插件

创建、升级和复用插件前请读 [插件创建规范](handoff/PLUGIN_SPEC.md)（含时间插件、权限、生命周期、AstrBot 兼容路线）。

**时间上下文**与**时段寒暄**现在是真正的独立目录插件：

- `extensions/plugins/time-context/`
- `extensions/plugins/daypart-greetings/`

每个目录包含 `plugin.json`、`main.py`、`_conf_schema.json`。APP 扫描清单并加载入口；插件页每行有启用复选框和“设置”按钮。先选角色，调整参数，再点击外层“保存设置”，下一次发送生效。取消外层设置不会应用参数。异常清单会显示错误；删除目录即不再加载。Python 插件拥有当前用户权限，只安装可信代码。

时间插件可选择同时注入日期与具体时间，或只注入日期，不显示气泡。寒暄参数按角色独立配置：连续聊天免寒暄间隔默认 **60 分钟**，本次与该角色上次用户消息间隔不超过该值时不寒暄（跨时段也一样）；超过间隔重新寒暄。设置为 0 则恢复“每天每时段首次”。凌晨重复提醒可单独开关和设置间隔，开启时优先于连续聊天免寒暄规则。

八时段为凌晨 00–05、清晨 05–08、早上 08–11、中午 11–14、下午 14–17、傍晚 17–19、晚上 19–22、夜间 22–24（系统本地时区）。同角色多会话共享触发记录，不同角色独立。首次发送或长时间未聊后，本地触发短控制信息，要求模型在正常回复中包含当前时段的问候，再回答正文。措辞由角色表达，回复正常进入历史，工具后不再重复注入。控制信息不显示为气泡、不长期积累，不增加请求次数，但有少量输入 token；真实模型仍可能不遵循要求。

状态在 `data/plugins/daypart-greetings/state.sqlite3`。无正文的失败/取消会释放触发状态，避免失败就用掉寒暄；停止撤回也释放对应触发。空闲和 `/compact` 不触发。旧版固定气泡仍只读显示，并在启用插件的原会话请求中补入历史；新模型回复天然支持分支与导出。

文件工作台、持久记忆、MCP 桥的全局开关仍在插件页。旧单文件 JSON 提示词插件仍支持导入、按角色启停与设置，例如：

**QQ 定时提醒**（`extensions/plugins/qq-reminders/`，默认启用）：任意角色可用 `add_reminder / list_reminders / remove_reminders` 工具创建提醒（"22:30 提醒我睡觉"、"每晚必做清单（循环）"），到点由 QQ 机器人私聊发送，消息前缀角色名。规则：给出明确时间点才创建，模糊时间（"晚上"）先反问；说"每天/循环"即为每日重复。发送由**无窗口后台守护进程**（pythonw，15 秒轮询、接近零资源占用，`install_task.bat` 注册为任务计划程序的看门狗任务，每小时自动拉起、单实例锁）负责；QQ 网关（Rui 侧 dsh qqbot）在线且网络可用时送达，**断网/网关挂起的时段不丢提醒**：挂起重试（最多 5 次）后放弃并写入 `data/plugins/qq-reminders/daemon.log`。可选 LLM 润色默认关闭（零成本），开启走宿主 API 配置（Agnes 等），每天上限 10 条。提醒规范见 `extensions/skills/qq-reminders/SKILL.md`（可在设置 → Skills 为角色导入；插件自带的 system_context 已含基本规则，导入 Skill 不强制）。分发源码时 `extensions/plugins/qq-reminders` 必须随包携带；守护进程只在 Windows 本机运行。

```json
{
  "id": "daily-planning",
  "name": "每日计划",
  "prompt": "整理每日计划时，先确认可用时间，再列出三项优先事项。"
}
```

导入后复制到 `extensions/plugins`，勾选角色才加载。该格式是 Sunday Blue 的声明式提示词插件，**不是** Claude Code 插件包的直接兼容层，不执行任意插件代码。

## Skills

**设置 → Skills**：选择角色，导入包含 `SKILL.md` 的文件夹，再勾选启用。文件夹名使用英文字母、数字、短横线或下划线。程序只复制并加载 `SKILL.md`（最大 64 KiB），不自动执行 scripts，不自动读取 references；需要附件或 CLI 的 Skill 必须先改造成此宿主支持的流程。

已启用的 Skill 会加入下一次请求的系统提示，不需要每次手动声明。导入文件会立即复制到本软件；取消设置只取消启用选项，不撤销已导入的文件。

## MCP

先在 **插件** 页启用 MCP 桥，再在 **MCP** 页填写配置：

```json
[
  {
    "name": "my-service",
    "command": "C:/runtime/node.exe",
    "args": ["D:/my-mcp/server.js"],
    "roles": ["rui", "mia"],
    "enabled": true
  }
]
```

支持本地 **stdio JSON-RPC**，初始化、工具列表分页和工具调用。可选 `cwd`、`env`。需要可执行程序路径；不要把整条 shell 命令塞进 command。Windows 的 .cmd 包装器需要你明确配置 `cmd.exe` 及参数，程序不会隐式启用 shell。

每轮会话发送前，可用服务由角色授权筛选；启动外部程序和每次 MCP 工具调用都弹出确认。**MCP 进程拥有当前 Windows 用户权限，不受内置文件工具的目录规则限制。** 只接入自己信任的服务。服务返回错误/超时不伪造成功，超时后先核实实际结果。

当前不支持远程 HTTP MCP、OAuth、MCP resources/prompts/sampling，也未预装 TickTick / 幕布真实连接。MCP `env` 配置以明文保存，优先让服务自行读取凭据。

用户自行配置的外部 MCP 运行时/脚本是可选外部依赖；若你需要迁移或删除其所在文件夹，也应把这些运行时和脚本移入 Sunday_Blue 并更新配置。
