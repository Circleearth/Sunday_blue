# 学习、契约与状态估算

## 入口和复用边界

- **成长 → 学习与复习**：课程 → 章节 → 知识点；练习、错题、自评、复习与绑定番茄钟。
- **成长 → 限时契约**：签约、进展、核对结算、积分上限设置。
- **生活 → 恢复站**：现有状态卡展示独立的视疲劳/专注状态；新增离屏休息、恢复自动、状态参数。
- **日程 → 日历 / 提醒 / 打卡**：原组件直接嵌入，功能和数据库不变；旧导航键兼容。

没有新增计时器奖励引擎、第二套QQ客户端或替代记忆模块。学习时长仍来自 `activity_records`，金币仍由原 Focus 结算；契约/视疲劳消息写入共享 `reminder_occurrences`，由原异步投递服务发送。

## 学习：投入与证据分开

`modules/learning.py` 拥有 learning_* 表：层级、练习批次、复习、错题、计时关联和首次掌握里程碑。记录属于共享学习领域，不由人格持有；总负责人和学习负责人可通过现有 duty_action summary 读取必要摘要，无新增角色私有副本。

- 从知识点启动学习番茄钟，该轮绑定固定知识点，自动循环继续继承。未绑定的旧学习记录仍计入总时间，不猜测属于哪个知识点。
- 课程/章节/知识点三层；章节“已读完”独立于知识点掌握数量。时间增长不自动提高掌握度。
- 证据分：近50批练习正确率与自评的较小值。题量不足时最高59；没有练习时为0。
- 默认掌握条件：至少10题、证据分≥80、最近一次复习通过、没有未解决错题。阈值与最低题量可调。人为录入是用户自报证据，不声称系统自动验证了真实理解。
- 错题保留原因，重做成功才解决；练习幂等ID防止同一请求重复写入。复习每知识点每天一次，连续通过的间隔为1/3/7/14/30天；失败次日重检。
- 首次掌握里程碑与当前掌握状态分离，后者可以因新错题或失败复习下降。契约“新掌握”按首次里程碑计数。
- 当前版本支持新增层级与更新自评/章节进度，不提供批量删改练习或自动生成试卷。不要为补此功能无授权删除真实记录。

## 契约：有限、独立的游戏积分

`modules/contracts.py` 拥有 challenge_contracts / challenge_logs / challenge_ledger。

学习与运动契约积分各初始100、独立记账，**不等于学习金币、工作积分或现实预算，不能兑换现实奖励**。避免无限自报挑战影响已有商店经济。

- 支持有效学习分钟、首次掌握数量、通过复习次数、正确题数、自主目标完成量。
- 签约后冻结目标、截止、倍率和上限；更改设置只影响未来契约。截止最多一年，同时最多10份待处理契约。
- 基础10积分，奖惩倍率0–3；默认单次扣分≤30、每日≤60，可调但硬上限分别50和100。余额最低0。单次奖励硬上限90。
- 自动指标只计签约后、截止前的新证据；签约记录保存来源行基线，排除已有数据。同一事件不可重复结算。
- 达成自动结算。到期证据不足进入“待核对”，不会把没记录当成没做。用户核对失败或主动解约后才扣分；扣分事务同时限制单次、当日总额和可用余额。
- 自主目标需填写实际完成说明，不允许期限后补增量冒充期限内完成。第一阶段不做回溯证据仲裁，确有漏报可保留待核对，不自动处罚。
- 签约、到期、结算与每天18点后的进度通过共享电脑/QQ提醒；每天一次稳定ID，重启不重发已确认通知。非紧急契约提醒遵守既有恢复保护；投递失败可在日程提醒页检查和重试。真实QQ需原有渠道配置。

## 独立状态估算

`modules/attention.py` 的 attention_state/day/sleep 表与旧生活事实及体力成长表分离。新系统从眼疲劳0、专注100开始，这是估算起点而非测量结果；不反推全部历史用眼。当前状态卡读取新值，体力继续读取原有记录模型。

默认参数（均可在状态参数调整）：

| 行为 | 视疲劳 | 专注 |
| --- | --- | --- |
| 持续用眼每分钟 | +0.35 × 强度 | −0.18 × 强度 |
| 纸面学习每分钟 | +0.35 × 0.7 | −0.18 |
| 有效离屏休息每分钟 | −0.65 | +0.25 |
| 已确认睡眠每小时 | −7 | +6 |

强度为低0.7、中1、高1.4；状态限定0–100。离屏休息不直接恢复体力；生活正计时的恢复记录也不再直接增加体力。睡眠对旧体力参考的既有作用保留。

- 自动模式仅取Windows最后输入活跃度与当前番茄钟状态，不读屏幕内容、应用名称、按键内容或摄像头。
- 本轮改为日间09:00–22:00默认累积（软件运行时），学习/工作专注每分钟额外+0.15，参数可调；夜间实际输入活跃或专注仍进行时继续累积。短/长休息切到离屏模式，开始专注/生活计时切回自动。早9点分档结转和晚22点检查见 [日常状态与结算](DAILY_EXPERIENCE.md)。
- 被动阅读/看视频无法由鼠标键盘可靠判断，应选“持续用眼”；纸面学习也有眼负荷。休息模式下仍使用鼠标键盘时优先计入用眼。
- 单调时钟每5秒持久化，超过30秒停顿不补记；关闭软件和系统休眠不假装持续使用或已经休息。离线睡眠通过真实上报补充。
- 当前/昨日首次确认睡眠可恢复一次；保守扣除该夜两日内已经计入的休息量，避免重复恢复。修改同日睡眠不再次恢复状态；历史补记不回溯改写当前值。
- 默认60%本机轻提醒，80%电脑+QQ并打开非阻塞休息引导。状态回落到轻阈值以下10点才重新准备提醒；默认60分钟冷却，高阈值首次升级可以立即提醒，不持续刷屏。休息引导不强制中断任务、不扣金币。
- 参数窗口可滚动，支持调整增长/恢复率、阈值、冷却和夜间时间；不把这些参考数值作为医学结论。

## 验证与维护

服务：learning / contracts / attention；共享消息入口：notices.notify；编排仍在 ModuleHub。UI位于 module_views/growth.py、attention_controls.py；既有 life.py 页面只增加状态控制。

全量：`python -m unittest discover -s tests -v`。
专项：`python -m unittest discover -s tests -p test_growth.py -v`。
隔离页面预览：`python scripts/preview_growth_ui.py`。只生成测试记录，不发送QQ。

所有新表为增量创建，不重写原金币、聊天、人格、记忆或生活历史。回滚代码后新表保留，旧版本可继续使用旧表；不要为了回滚清空用户数据库。按现有规则由用户选择何时重新构建。

本轮新增每日足额运动契约及专注上限消耗，详细边界见[日常状态补充](DAILY_EXPERIENCE.md#后续补充控制契约与工作层级)。
