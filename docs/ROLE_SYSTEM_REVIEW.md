## 开发顺序

1. 统一角色注册、创建/重命名/归档/恢复/安全删除，接通所有角色消费者，验证重启与隔离。
2. 验证最终请求中的人格层，复用现有插件/工具接口增加可控能力绑定与条件加载；保留默认行为。
3. 受控结构化记录与协作接口，区分推断/决定/任务，不自动将推断升级为事实。
4. 模型与推理仅给方案：角色覆盖全局连接、显式供应商能力表、请求诊断；未知服务默认不发送未声明参数，不能静默标记“高推理”。本轮不实现自动路由或额外付费语义调用。

## 安全约束

真实用户记录不用于删除测试。已有未提交修改备份于 `.cache/role-refactor-checkpoint/before.patch`，不重置。角色删除只处理明确归属；未知插件、外部执行器和待发 QQ 提醒必须先解除依赖。共享插件代码、Ollama 模型、外部工作区、全局凭据不在删除范围。旧备份是离线恢复资料，不能当作活跃记忆检索；删除并不代表取证级擦除。

## 阶段 1：角色生命周期

统一注册落在 `roles.py` / `data/roles.json`；默认九角色只用于首次初始化。旧 ID 原样保留，新 ID 使用 UUID，名称不用于路径。`storage.ROLES` 是旧插件兼容读取器，不再是真实注册来源；`ROLE_IDS` 仅为旧外部导入保留，宿主验证已全部改为按安装根读取注册。

`role_lifecycle.py` 负责依赖检查、归档/恢复、导出和删除日志；`role_preferences.py` 负责范围展示和用户确认。所有选择器、会话创建、人格读取、记忆队列与后台启动使用同一注册。至少保留一个启用角色。正在生成、记忆图谱打开、记忆操作执行、待发 QQ 提醒、启用的 MCP 绑定、未知插件数据会阻止归档/删除。未触碰 QQ 插件源码或调度钩子。

永久删除要求先归档，再输入显示名。先产生并校验 `data/role_operations/<操作 ID>/backup.zip`；写批准日志后逐项清理，角色 `deleting` 状态禁止执行。故障保留日志与备份，重启或“继续未完成的删除”幂等续做，失败不会报告成功。完整 ZIP 包含归属文件、会话/消息/审计、已知共享库中的角色行、角色配置/字体/MCP 关联清单；不复制全局 API 密钥。`deleted` 身份墓碑保留防止 ID 重用。离线恢复文件仍含个人资料，不自动清除。

删除会话与删除角色严格区分：前者移除原文与来源队列，保留已经提炼的角色记忆。去掉了猜测上游表名的清理和吞错误行为；如需遗忘所有角色记忆，应使用角色删除，不能误称会话删除已完成遗忘。

新角色 UI、归档与删除中断恢复专项测试已通过；最终全量结果见交接。

## 阶段 2：人格与能力边界

`capabilities.py` 是轻量的单回合路由，不引入框架。Role 保持身份；Capability 表示已授权绑定；Tool 仍是现有执行接口；Skill 仍复用文本流程；Workflow 目前只有加载条件与本轮状态，不冒充通用工作流引擎。Memory 仍区分确认记忆与自动历史记忆。

角色权限页可单独设置文件、确认记忆、MCP 能力和职责范围。插件/Skill 的授权仍使用原页面。每个绑定可选择每轮加载或按需加载，并配置逗号分隔的字面关键词；`@skill:名称`、`@plugin:插件ID`、`@files` 可确定性触发。未触发时只提供已授权能力的短目录，普通对话模型可用 `activate_capability` 申请，再在下一次工具续接请求加载正文/工具。无独立分类模型，无额外分类提示词常驻；工具续接仍产生正常 API 用量。没有授权的能力不能申请。时间与寒暄仍由本地时段规则控制。

已配置角色保留原默认加载行为，新角色默认不继承自动启用插件，也不开放文件/MCP 能力。Mia/Kia/Rui 的当前职责通过可编辑运行范围表达，原有人格 Markdown 不改写。人格仍每回合读取四个文件；API 请求验证覆盖两个协议、四字段一次注入、保存后更新、改名和跨角色隔离。只验证请求内容正确，不声称外部真实模型必然服从人格。

## 模型 / 推理审查方案（本轮不实施）

当前只有全局连接；usage 是会话最近一次值，不是完整逐请求账本。Anthropic thinking_budget 只判断输出预算是否充足，没有型号/中转商能力检测，OpenAI 分支没有 reasoning_effort。不能称其为“自动高推理”。

下一轮建议：连接配置保持共享且 DPAPI 密钥只存一份；角色选择 connection_id/model 及显式 reasoning policy 覆盖默认。供应商适配器声明支持字段、范围、默认值与不支持行为；未知中转默认不发送推理参数，UI 明确未启用。Rui 可由用户选择已验证支持的高推理配置，其他角色沿用默认。复杂度规则先由任务类型/显式“深度复盘”决定，需要语义判别时复用当前模型的受控调用；不悄悄额外请求付费分类模型。新增逐请求 model/protocol/elapsed/usage/error_code 诊断，避免记录密钥和正文。真实兼容性只能用用户实际供应商的明确测试确认，本轮未进行付费探测。
