# Markdown 资料书写规范

适用：记录员、整理员编写或修改用户授权目录内的 Markdown。规范只约束文档格式，不授予文件权限，也不把推测变成事实。

## 先查再写
- 先检索相关目录与同主题文件，优先追加或修订已有文档；不要每次新建文件/目录。拿不准分类或合并关系时询问用户。
- 文件名简短且有检索意义，如 `项目A-会议记录.md`、`2026-11-11-日记.md`。日期只用于真实有日期的记录，不凭空补时间。
- 默认复用已有分类，避免重复“资料/新资料/最终版”目录和过深层级。日历完整记录归入已有“日记完整记录”。

## 文档结构
- 使用 UTF-8；一个一级标题 `# 标题`，其下用 `##` / `###` 分节，不跳级。标题上下留空行。
- 开头用 1–3 句说明主题或来源；事实、用户确认决定、待办、AI 建议分别注明，未知写“待确认”。快速原文记录可以只有标题、来源和正文，不为套模板反复扩写。
- 列表使用 `- `；任务使用 `- [ ]` / `- [x]`，只有明确完成才勾选。表格用于简短对比，不把长正文塞进表格。
- 代码使用带语言名的围栏代码块；引用原话用 `>`，保留原义与来源。
- 文档互链、图片优先用当前资料库内相对路径，如 `[项目索引](../项目A/索引.md)`；链接可包含中文和空格，不写绑定某台电脑的绝对路径。不要自动添加外网图片、跟踪像素或可执行 HTML。
- 普通文档不用 HTML 排版、脚本、复杂插件语法。超长主题拆成有明确关系的文档，并在已有索引中加入链接，不造一堆空索引。

## 分工与修订
- 记录员快速保存用户原文与必要出处，复杂分类/重复项判断交给整理员；不把没记录当成没执行。
- 整理员先读取交接和相关原文件；保留原文、已有链接及历史，合并/移动前核实权限和引用。失败留交接，不伪称完成。
- 修订时只改相关段落，必要时在文末记录日期和修改摘要；不要捏造更新时间、作者或已完成事项。任何真实文件修改必须以工具回执为准。
