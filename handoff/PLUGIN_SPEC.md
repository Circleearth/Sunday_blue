# Sunday Blue 插件创建规范 v1

这是插件开发的唯一规范入口。README 与 HANDOFF 只链接此文件；维护时先确认实现是否支持，不能把规划当成功能。2026-11-03 更新。

## 1. 先选插件类型

| 类型 | 放置位置 | 执行方式 | 权限 |
|---|---|---|---|
| 声明式提示词插件 | extensions/plugins/<id>.json | extensions.extension_text 加入 system | 无独立文件/网络/代码权限 |
| Skill | extensions/skills/<id>/SKILL.md | 按角色启用并注入文本 | 不执行脚本，不自动加载附件 |
| 内置宿主插件 | sunday_blue/<职责模块>.py | 代码显式导入和调用 | 必须逐项审查，不能动态扫描执行第三方 Python |
| MCP 服务 | 设置 MCP 页配置，本地 stdio | 独立进程，初始化、列工具、调用 | 进程有本机用户权限；需启动及调用审阅 |
| AstrBot 插件 | 当前不支持直接加载 | 必须由 AstrBot 原生运行时承载 | 不能假设 Sunday Blue 的目录权限约束它 |

当前没有通用 Python 插件安装器或自动市场安装接口。不要在 JSON 中添加 module/entrypoint 然后声称会执行；不使用 eval、exec 或动态 import 用户输入。

## 2. 创建提示词插件（可立即使用）

UTF-8 JSON，文件名与 id 一致，ID 使用小写字母、数字、短横线；导入器当前也兼容大写与下划线，新插件统一小写。文件不超过 64 KiB。

```json
{
  "id": "daily-planning",
  "name": "每日计划",
  "version": "1.0.0",
  "description": "帮助整理优先事项",
  "author": "维护者名称",
  "license": "填写实际许可证",
  "prompt": "整理计划前先确认可用时间，不虚构已经创建的日程。"
}
```

运行器实际读取 prompt；设置导入器要求 id 和 prompt。name/version/description/author/license 是维护元数据，当前没有自动依赖解析、版本迁移或许可证验证。元数据不得伪造。

操作：设置→插件→导入 JSON→选择角色→勾选→保存；下一次发送生效。默认不跨角色启用。删除插件前先取消对应角色勾选。升级保持 ID；先备份旧文件，再替换并测试；回滚恢复旧文件。当前导入器拒绝同名覆盖，升级须维护者明确进行。取消设置不会撤销已复制的导入文件。

提示词应说明触发条件、输出要求、失败处理；不得覆盖宿主权限、泄露凭据、假装执行成功、自动改变人格或要求全盘扫描。插件内容属于低信任扩展，不得凌驾宿主规则。多个插件冲突时保留宿主约束，并减少冲突插件；当前加载顺序为角色配置列表顺序，没有 priority 字段实现。

## 3. 创建内置宿主插件

仅在动态数据或真正功能无法由静态提示词完成时使用。每个模块有明确职责、版本常量、显式入口；无 import 时网络请求、进程启动、数据库写入或无限后台线程。主逻辑采用可注入参数的纯函数，UI、Provider、数据库不能互相循环依赖。

接入步骤：
1. 写明输入、输出、调用时点、错误语义、是否必需、影响角色和权限。
2. 独立模块实现；在最小调用点显式导入，避免复制整份 Agent/UI。
3. 动态上下文只放 system，不把元数据新增为 user/assistant 消息。工具返回保存真实回执；失败不能冒充成功。
4. 配置必须有默认值和老版本兼容；写入仍走权限与审阅。没有设置 UI 时明确声明，不能假装可切换。
5. 执行生命周期明确：每轮、每次模型请求或启动时，三者不能混用；停止、异常、资源回收分别测试。
6. 增加单测和必要集成测试，更新本规范、维护地图、自己的交接记录；不需要为无副作用常量堆叠测试。

### 已实现示例：time-context 1.1.0

入口 `sunday_blue/time_context.py:time_context(moment=None)`；由 `agent.system_prompt` 显式调用。由 `native_plugins.py` 显式登记，在设置→插件中显示，按角色独立启停；默认启用。角色配置 `native_plugins/time-context` 保存布尔值，旧配置缺省兼容。它仍是宿主 Python 插件，不是提示词 JSON 插件，不动态执行用户代码。

时间取操作系统本地时钟与时区，精确到分钟，包含 YYYY-MM-DD、星期、HH:MM、UTC 偏移。每次开始处理用户消息/重试构建 system 时刷新；同一轮工具往返保留该轮时间快照，不承诺每个工具请求重新采样。空闲时无需午夜定时器，午夜后的下一轮自动换日。压缩整理器不需要当前时间，不注入它，避免把历史“今天”错改成当前日期。历史气泡、数据库消息均不增加时间元消息。

输出策略：时间只是背景；不例行报时、不连续问早晚好、不无关劝睡/催饭，不虚构离线生活、提醒或用户活动。只有询问时间、期限、作息等相关请求才提及。模型仍有随机性，提示词约束不等于绝对保证不说时间。

选型理由：每轮日期+时间比“每天独立更新日期、另行注入时间”少一个状态来源，跨日、重开、时区变化更一致。自然度来自按需表达，不是注入频率本身；这是工程选择，尚未做用户 A/B 实验。测试覆盖跨午夜、UTC 偏移、九角色入口、不落聊天消息、重复调用刷新。

## 4. MCP 工具插件合同

配置字段：name、command、args（字符串数组）、roles（明确角色 ID）、enabled；可选 cwd、env。仅 stdio；不宣称 HTTP/OAuth/resources/prompts/sampling 已实现。协议初始化与工具 schema 由 extensions.py 管理。

工具名称唯一，描述说明副作用，inputSchema 明确类型/必填项。超时意味着结果可能未知，先查询状态再重试。重要写入应设计幂等键和读回检查。不得在日志、Git 或错误文本中输出密钥；env 当前明文保存，优先外部凭据存储。服务及其子进程的清理由服务作者负责验证，不能仅凭关闭父进程声称全数终止。

外部服务有本机权限，不是沙箱；内置路径检查不自动覆盖 MCP。不要为了安装插件关闭目录授权、证书验证或审阅流程。

## 5. 发布、更新、回滚与验收

每个插件附用途、版本、入口、配置示例、依赖版本、数据位置、权限、错误/超时语义、卸载/回滚方式、许可证和上游来源。源码与配置模板可进 Git；真实用户数据和凭据不进。运行数据按角色/插件隔离，建议 data/plugins/<id>/<role>/，但需实现明确的存储接口，目录约定不代表已有 API。

变更数据库或格式需提供迁移版本、备份和降级策略，不允许静默丢弃字段。依赖固定可复现版本，网络安装不是加载插件的副作用。第三方更新先检查 diff、依赖和权限，再测试，不自动下载执行“最新版”。

验收至少检查：有效/无效配置、启停/角色隔离、错误与超时、取消、重复请求、敏感数据不泄露、消息不被元数据污染、旧配置仍可读。涉及文件或网络工具时验证越权拒绝及真实回执。运行全量 tests；真实服务未测必须标注。发布前更新 handoff，按仓库约定提交同步；本阶段不打包。

## 6. AstrBot 复用路线（评估，未接入）

建议保留 Sunday Blue 桌面 UI/人格/数据，把 AstrBot 作为**可选独立服务**，通过明确桥接调用原生插件。这最接近复用原插件，避免自己重造 AstrBot 的事件、平台和插件运行时。不能把 AstrBot 的 metadata.yaml/main.py 放入 extensions/plugins 就认为安装成功。

分三类验证：纯函数/HTTP 工具可抽取业务逻辑或包装成 MCP；消息事件/命令/Provider 钩子应在 AstrBot 内运行并做会话桥接；QQ/群管理/平台消息链插件依赖真实平台事件，桌面聊天没有这些语义，不能保证兼容。

桥接必须解决：role+session ID 到独立 AstrBot 会话的映射，分支、取消和重试幂等，流式响应，工具审阅，唯一记忆权威，附件/消息链降级，鉴权及角色隔离，外部进程权限。不要同时让两套 Agent 自动处理同一轮或两套长期记忆互相覆盖。先以固定版本 AstrBot + 一个纯查询插件做 PoC，再验证一个有副作用的插件，最后决定是否替换核心。当前未安装 AstrBot、未实现桥、未承诺插件市场全兼容。

可参考插件市场的元数据、生命周期、配置隔离与兼容性声明，但模型 API wire 协议仍须按服务商规范；开源框架不能消除协议要求。AstrBot 主仓库标注 AGPL-3.0；各插件许可证独立核对，复用前保留来源与许可证，发布修改版前审查对应义务。

## 7. 已实现示例：daypart-greetings 1.0.0

入口 `daypart_greetings.Greetings.on_message(config, role, sid, message_id, moment=None)`。UI 在保存普通用户输入后调用；`/compact`、重试、工具轮次不调用。无网络、无模型调用、无提示词注入。`native_plugins.py` 登记名称版本，设置插件列表基于 itemData 区分 native/prompt，不能把 native ID 当 JSON 文件名读取。

时段表及本地文案位于 daypart_greetings.py；首次键为 role+local date+period，同角色会话共享。凌晨每次主动消息可提醒，配置 greetings/night_repeat 与 night_interval_minutes（默认 true/0）；其余时段仅首次。单条用户消息以 session+message_id 保证幂等；SQLite BEGIN IMMEDIATE 保证并发互斥。独立插件库 `data/plugins/daypart-greetings/state.sqlite3` 存 seen/events，不改主数据库 schema，不进入 memory/system/messages。插件库失败只写 audit，不阻塞模型请求；不自动重试生成重复气泡。

宿主 UI 在对应用户消息之后展示本地气泡，并标明来源。关闭插件保留历史，设置从下一条消息生效。当前分支和 Markdown 导出不含本地气泡；重新开启不清空当天首次记录。后台无独立推送或定时催睡。文案是本地固定模板，不宣称由 LLM 生成。

新增类似插件时仍需独立模块、显式注册、按角色配置、明确调用点与数据归属；禁止为了展示寒暄把事件混入模型消息。备份保留 data/plugins；卸载/关闭不能连带删除用户会话。测试覆盖边界、跨日、角色隔离、跨会话/重启、幂等、间隔、开关独立性、UI可见性及模型历史不含插件文案。
